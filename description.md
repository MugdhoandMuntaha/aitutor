# AI STUDY COMPANION

## A RAG-Powered Personalized Learning Platform Built with Flutter

**Project Type:** AI / Mobile Application / RAG / Educational Technology
**Frontend:** Flutter + Dart
**Backend:** Supabase + PostgreSQL + pgvector + Edge Functions
**AI Layer:** Large Language Model + Embedding Model
**Platforms:** Android, iOS, Web/Desktop optional
**Target Users:** University and college students

---

# 1. Project Overview

## 1.1 Project Name

**AI Study Companion**

A personalized AI-powered study assistant that allows students to upload their own academic materials—PDFs, lecture notes, slides, textbooks, images, and documents—and interact with those materials using natural language.

Instead of simply asking an AI general-purpose questions, students can ask questions such as:

> "Explain CPU pipelining from my Computer Architecture lecture notes."

The system retrieves the most relevant sections from the student's uploaded material and uses them as context for the AI response.

The response can also include:

* Source citations
* Page numbers
* Relevant documents
* Simple explanations
* Examples
* Follow-up questions
* Quiz questions
* Flashcards
* Related topics

The application therefore acts as a **personal AI tutor built around the student's own knowledge base**.

---

# 2. Core Idea

The main concept is:

**Student → Upload Study Materials → AI Processes Materials → RAG Knowledge Base → Ask Questions → Retrieve Relevant Knowledge → AI Generates Answer → Show Sources**

The important difference from a normal AI chatbot is that the system does not rely only on the LLM's general knowledge.

Instead:

**User Question**

↓

**Query Understanding**

↓

**Semantic + Keyword Search**

↓

**Relevant Chunks from Student's Materials**

↓

**Context Construction**

↓

**LLM**

↓

**Grounded Answer + Citations**

This is the fundamental RAG pipeline.

Supabase's current AI tooling supports semantic search, keyword search and hybrid search using PostgreSQL and pgvector, making it a practical choice for this architecture.

---

# 3. Problem Statement

Students commonly face several problems:

1. Study materials are scattered across PDFs, slides, notebooks and cloud storage.
2. Searching large PDFs manually is slow.
3. Generic AI assistants may provide information unrelated to the student's course material.
4. Students may not know which topics they understand poorly.
5. Creating quizzes and revision materials manually takes time.
6. Students often study without a structured plan.
7. It is difficult to maintain a personalized knowledge base for every course.
8. Answers generated by AI may be difficult to verify without references.

AI Study Companion attempts to solve these problems in one application.

# 8. RAG Pipeline

The RAG system is the heart of the project.

## 8.1 Step 1 — Document ingestion

Suppose a student uploads:

**Computer Architecture Lecture 05.pdf**

The backend extracts the text.

---

## 8.2 Step 2 — Chunking

The document is divided into smaller sections.

For example:

```text
Document
   ↓
Page 1
Page 2
Page 3
   ↓
Paragraphs
   ↓
Chunks
```

A chunk might contain approximately 300–800 tokens depending on the chosen strategy.

Each chunk should retain metadata such as:

```text
document_id
course_id
page_number
section_title
chunk_index
content
```

This is extremely important because the application can later tell the user:

> Source: Computer Architecture Lecture 05, Page 7

---

# 9. Embeddings

Each chunk is converted into an embedding vector.

Conceptually:

```text
"Cache memory stores frequently accessed data..."
```

becomes:

```text
[0.021, -0.183, 0.492, ...]
```

The vector represents the semantic meaning of the text.

These embeddings can be stored in PostgreSQL using the **pgvector** extension. Supabase officially supports vector columns and similarity search through pgvector.

---

# 10. Query Processing

Suppose the user asks:

> "Why is cache memory faster than RAM?"

The question is converted into an embedding.

The system searches the vector database for semantically similar chunks.

For example:

```text
Query
 ↓
Embedding
 ↓
Vector Search
 ↓
Top 5 relevant chunks
```

The system might retrieve:

```text
Chunk 1 — Cache hierarchy
Chunk 2 — SRAM vs DRAM
Chunk 3 — Memory access latency
Chunk 4 — CPU cache
Chunk 5 — Locality of reference
```

# 11. Hybrid Search

A particularly strong improvement is to use **hybrid retrieval** instead of vector search alone.

Combine:

### Semantic Search

Finds content based on meaning.

### Keyword Search

Finds exact terms.

### Metadata Filtering

Filters by:

* Course
* Subject
* Document
* Semester
* Page
* Topic

Supabase supports semantic, keyword and hybrid search patterns through Postgres/pgvector.

The final retrieval system can therefore be:

```text
                    User Question
                         │
             ┌───────────┴───────────┐
             ↓                       ↓
      Semantic Search          Keyword Search
             │                       │
             └───────────┬───────────┘
                         ↓
                  Result Ranking
                         ↓
                  Top K Chunks
                         ↓
                  LLM Context
```

This can improve retrieval for technical terms such as:

```text
DFA
TCP
ACID
CAP theorem
8086
RISC
CPI
OOP
SQL JOIN
```

# 12. AI Answer Generation

The retrieved chunks are passed to the LLM as context.

Conceptually:

```text
System Instructions

+

User Question

+

Retrieved Knowledge

+

Conversation History

↓

LLM

↓

Answer
```

The system prompt should instruct the model to:

1. Prefer retrieved sources.
2. Avoid inventing information.
3. Clearly distinguish source-based information from general knowledge.
4. Cite relevant sources.
5. Say when the uploaded materials do not contain enough information.
6. Explain concepts at the student's selected difficulty level.

# 16. Socratic Learning Mode

# 45. Security Architecture

Security should not be an afterthought.

Implement:

### Authentication

Email/password and optionally Google sign-in.

Firebase is also a viable alternative for authentication and notifications in Flutter; Firebase provides official Flutter integration and authentication support.

### Authorization

Users should only access:

```text
Their own documents
Their own chats
Their own quiz results
Their own study plans
```

### Row Level Security

Use PostgreSQL/Supabase RLS.

For example:

```text
User A
 ↓
Can access
 ↓
Only User A's documents
```

not:

```text
User A
 ↓
All documents
```

Supabase specifically supports RLS-based permission filtering for RAG systems.

# 46. AI Hallucination Prevention

This is one of the most important technical challenges.

The AI should not confidently invent information.

Use rules such as:

```text
If sufficient retrieved context exists:
    answer using the context

If context is insufficient:
    say that the uploaded material does not contain
    enough information

Do not fabricate citations.
```

The UI should distinguish:

**Based on your materials**

from:

**General AI explanation**

This gives the user a clearer understanding of where an answer came from.

# 73. Cost Control

AI applications can become expensive.

Use:

### Smaller embedding model

For document indexing.

### Smaller model

For simple tasks:

```text
flashcards
classification
summaries
quiz generation
```

### More capable model

For complex reasoning.

### Caching

Cache repeated requests.

### Retrieval limits

Don't send 30 irrelevant chunks to the LLM.

Use a small number of high-quality chunks.

# 74. Important Design Principle

Do not make the LLM responsible for everything.

Use conventional software for deterministic tasks.

For example:

```text
Calculate quiz score
→ Backend code

Store document
→ Database

Search vector
→ pgvector

Generate explanation
→ LLM

Detect weak topic
→ Analytics + AI

Create study plan
→ AI + deterministic constraints
```

This makes the system cheaper, more reliable and easier to debug.
